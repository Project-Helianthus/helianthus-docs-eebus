# SPINE Protocol Specification 1.3.0

Datagram, addressing, classifiers, discovery, binding, and the command limits this specification prints. defaultMaxResponseDelay is 10 seconds (§5.2.5.3). A number that another shard states differently stays beside this one, tagged with its own clause.

## Concepts

| concept | meaning (own words) | clause |
| --- | --- | --- |
| device, entity, feature | Three levels. Entity address 0 of type DeviceInformation and feature address 0 of type NodeManagement are required. | SPINE Protocol Specification 1.3.0 §7.1 |
| feature role server | The feature holds the data and answers reads, writes, and calls. | SPINE Protocol Specification 1.3.0 §3 |
| feature role client | The feature requests or subscribes to a server feature. | SPINE Protocol Specification 1.3.0 §3 |
| feature role special | A role the specification marks special rather than plain server or client. | SPINE Protocol Specification 1.3.0 §3 |
| standard class | Basic functions, simple patterns, without deep nesting. | SPINE Protocol Specification 1.3.0 §1.2 |
| complex class | Built by recombining parts of standard classes. | SPINE Protocol Specification 1.3.0 §1.2 |
| device type | deviceInformation.description.deviceType is a standard type or a vendor-specific type. The type should not drive an automatism. | SPINE Protocol Specification 1.3.0 §7.1.1.1, §7.1.1.2 |
| vendor-specific type | The pattern is an underscore, then i: and a positive integer or n: and a token, then an underscore and a non-space name. | SPINE Protocol Specification 1.3.0 §7.1.1.1 |
| address string | A device part, then entity parts, then a feature part. The device address maximum is 256 characters. | SPINE Protocol Specification 1.3.0 §5.2.2, §7.1.1.2 |

## Command classifiers

| classifier | meaning | response | clause |
| --- | --- | --- | --- |
| read | ask the server for function data | reply carries the data; result reports refusal | SPINE Protocol Specification 1.3.0 §5.2.4 |
| write | ask the server to change function data | result acknowledges when requested | SPINE Protocol Specification 1.3.0 §5.2.4 |
| call | invoke a function that is not a plain read or write | result or reply as the function defines | SPINE Protocol Specification 1.3.0 §5.2.4 |
| reply | return data for a read | no further classifier is required for the reply itself | SPINE Protocol Specification 1.3.0 §5.2.4 |
| notify | send subscribed data without a new read | a client receives the notification | SPINE Protocol Specification 1.3.0 §5.2.4 |
| result | acknowledge a command | errorNumber 0 is positive; every other value is negative | SPINE Protocol Specification 1.3.0 §5.2.4, §5.2.5.2 |

## Acknowledgement and error codes

The protocol pages say 0 is positive and every other value is negative, and they do not list the codes. The resource specification and the binding clauses name the codes below. The annex restricts the type without a code list. All of these stay.

| code | meaning | clause |
| --- | --- | --- |
| 0 | positive acknowledgement, no error | SPINE Protocol Specification 1.3.0 §5.2.5.2; SPINE Resource Specification 1.3.0 §3 |
| 2 | timeout, where the resource specification lists it | SPINE Resource Specification 1.3.0 |
| 6 | command not supported, where the resource specification lists it | SPINE Resource Specification 1.3.0 |
| 7 | rejected command; also a refused binding request | SPINE Protocol Specification 1.3.0 §7.3.2; SPINE Resource Specification 1.3.0 |
| 8 | unsupported restricted combination, where the resource specification lists it | SPINE Resource Specification 1.3.0 |
| 9 | binding necessary, or a binding entry is required and missing | SPINE Protocol Specification 1.3.0 §7.3.5; SPINE Resource Specification 1.3.0 |
