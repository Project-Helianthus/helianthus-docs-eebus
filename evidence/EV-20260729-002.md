# Redacted Reconnect Topology Ordering Observation

- Evidence id: `EV-20260729-002`
- Evidence class: `observed_runtime`
- Capture date: not published
- Runtime class: Home Assistant add-on on a local LAN
- Peer class: previously trusted SHIP/SPINE gateway
- Acquisition method: owner-only local MCP plus runtime logs
- Artifact class: `shareable_redacted`
- Private artifact retained: yes
- Redaction mode: identities, addresses, raw values, tokens, network details,
  and binary digests omitted
- Publication status: publishable

## Observed Sequence

One restart returned the eeBUS runtime to `ready`, with one paired and connected
remote session. The first raw topology capture contained the remote device and
its device-level metadata but no entities, features, or use-case claims.

The topology snapshot remained byte-stable during the bounded observation
window. During that same connection generation, an exact owner-authorized
feature lookup returned the expected function declarations and an immediate
read-only data request returned a complete live reply with no failures.

Earlier starts of the same reviewed build and trusted identity had produced a
non-empty detailed topology. No collision-close, duplicate-connection,
state-wait close, panic, fatal result, trust loss, or durable mutation was
observed in the affected restart.

## Supported Inference

The live SPINE graph had converged far enough to service the exact feature
request, while the separately published raw topology snapshot retained an
earlier device-only observation. Source inspection shows that topology-bearing
events received before connected-session publication are currently rejected
by that ordering gate. Together, these facts support a candidate event-ordering
loss, not a transport disconnect or a semantic interpretation.

## Exclusions

This record publishes no peer identity, SHIP ID, SPINE address, feature name,
raw value, private address, token, certificate material, trust-store data, or
binary digest. It does not establish device behavior, a universal ordering,
write safety, promoted semantics, or a released fix.

## Falsification Criteria

The inference is falsified if a bounded replay shows that the existing
device-only snapshot converges without a later topology event, or if the exact
feature operation cannot succeed while that snapshot remains partial. A fix is
not accepted until both callback orderings, a concurrent crossing, stale
generation rejection, and a deployed restart are covered.
