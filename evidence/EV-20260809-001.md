# Home Assistant Full-Container eeBUS Restart

- Evidence id: `EV-20260809-001`
- Evidence class: `observed_runtime`
- Capture date: not published
- Device family: redacted SHIP HVAC gateway
- Firmware version: not published
- Add-on version: `0.6.33` candidate
- Add-on source under review:
  [`helianthus-ha-addon` pull request 170](https://github.com/Project-Helianthus/helianthus-ha-addon/pull/170)
- Gateway source:
  [`helianthus-ebusgateway` pull request 773](https://github.com/Project-Helianthus/helianthus-ebusgateway/pull/773)
- Runtime class: Home Assistant add-on with host networking
- Acquisition method: owner-authorized local MCP capture before and after a

- Private artifact retained: yes
- Redaction mode: pass/fail identity comparison, aggregate topology counts,

- Publication status: publishable

## Observed Restart

Supervisor removed the running add-on container and created a different
container from the same candidate image. The image-owned wrapper was used; no
persistent gateway executable override was active. The protected option set,
host-bound machine identity, and both trust-store manifest commitments matched
their pre-restart values.

Without opening pairing or performing a new trust action, the runtime returned
to `ready`. The same redacted peer was paired and visible, and one SHIP session
returned to `connected`. Stable raw facts extracted before and after recreation
were byte-identical after excluding container identity, capture time, session
generation, and envelope timestamps.

The authorized local raw topology reported:

| Observation | Count |
| --- | ---: |
| Remote protocol devices | 1 |
| Entities | 11 |
| Features | 20 |
| Use-case claims | 22 |
| Distinct use-case names | 13 |
| Distinct name-and-actor identities | 15 |

These counts describe raw SHIP/SPINE observations. They do not promote any
claim into a Helianthus semantic leaf.

## MCP Boundary

The owner-only Unix-domain MCP socket returned `mask_tier=raw` with operational
device, service, entity, feature, and use-case data. Two captures of the same
runtime snapshot produced the same content hash. A raw evidence reference was
successfully dereferenced only on that raw operator boundary.

The HTTP MCP surface returned `mask_tier=redacted`. The redacted payload did
not contain the retained peer SKI, SHIP ID, device address, entity address, or
feature address. Raw-on-public and redacted-on-raw dereference attempts both
failed with `permission_denied`. The temporary raw and redacted snapshots were
dropped after the boundary check.

No private key, PEM private material, token, trust-store byte, machine
identity, private network coordinate, protocol address, peer identifier,
container identifier, image digest, or private artifact hash is published in
this record.

## Scope Limitation

The physical eBUS adapter was unreachable during this run. The gateway used an
inert loopback eBUS transport so the eeBUS sibling runtime could remain active.
Repository coexistence gates were already exercised separately, but this
record does not claim a simultaneous live eBUS transport smoke test.

## Falsification Criteria

This record is falsified if the retained private evidence shows any of the
following:

1. Supervisor did not remove the original container or did not create a new
   one from the same candidate image.
2. Protected options, host-bound machine identity, trust manifests, stable
   peer facts, or raw topology identities changed across recreation.
3. Pairing was reopened, a new trust action occurred, the runtime did not
   return to `ready`, or the retained peer did not return to one connected
   session.
4. The raw topology counts differ from 1 device, 11 entities, 20 features, or
   22 use-case claims.
5. The public HTTP payload contains a retained operational identity or accepts
   a raw evidence reference, or the operator boundary accepts a redacted
   evidence reference as raw.
