## Observed Inputs And Outcomes

One bounded mDNS observation supplied a `.local` host, a concrete address set,
a port, and a path for the same SHIP service snapshot. No address, host label,
service identity, certificate identifier, or private network detail is
published.

In the baseline path, `.local` hostname resolution remained blocked long
enough for the outbound attempt to retain its lease and initiation ownership.
Inbound convergence was not observed during that bounded window. This was a
persisted-trusted reconnect attempt, not queued first trust.

A diagnostic build changed only endpoint order for the same observation: it
tried a concrete address before the hostname. That attempt connected in about
275 ms and the resulting session later exposed non-empty raw SPINE topology.
The public record does not retain the topology contents or assign semantic
meaning to them.

The diagnostic did not establish a universal resolver failure, a required
successful address family, a concrete-only policy, a trusted reconnect
guarantee, queued-pairing behavior, device behavior, or semantic support. It
did not test the case where all concrete addresses fail and the hostname
succeeds.

## Falsification Criteria

A bounded redacted replay under the same runtime conditions would contradict
the observed stall if hostname-first resolution repeatedly completed within
the attempt budget without retaining lease or initiation ownership. It would
contradict the diagnostic contrast if concrete-address-first dialing did not
connect or did not progress beyond the hostname-first baseline.
