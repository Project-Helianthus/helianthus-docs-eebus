# EV-20260811-002: VR940f Multi-Leaf Source Inventory

## Provenance

- Evidence id: `EV-20260811-002`
- Capture dates: 2026-08-11 and owner-authorized closure read 2026-08-12
- Device family: Vaillant VR940f
- Acquisition: owner-authorized local `eebus.v1.features.get` and
  `eebus.v1.features.data.get` raw reads over the existing trusted SHIP session
- Runtime release: Helianthus Home Assistant add-on `0.6.36`
- Private artifact retained: yes
- Redaction mode: shareable protocol fields, private native identity and
  topology selectors removed

## Observation

The live source inventory exposed seven numeric temperature sources, three
operation-mode fields, four boolean fields, two manufacturer metadata fields,
and two heating-zone labels. The protocol details also preserve the four
pre-existing terminal records as retired non-leaves. Numeric constraints were
read from `measurementConstraintsListData` or
`setpointConstraintsListData`, not inferred from rendered values.

The declared numeric steps were:

- DHW measurement and DHW absolute setpoint: `1 degC`;
- both room measurements and both room absolute setpoints: `0.5 degC`;
- outside-air measurement: `0.5 degC`.

All three HVAC sources described the same operation-mode relation:
`0=auto`, `1=on`, and `2=off`. The DHW HVAC feature additionally described
overrun id `0` as `oneTimeDhw`, affecting system-function id `0`; its observed
status was `inactive`. The three `isOperationModeIdChangeable` fields were
present and true in the closure read. They have no fabricated eBUS capability
source and therefore use the explicitly single-protocol
`EEBUS_NATIVE_CAPABILITY` validation mode.

The closure read also observed two distinct non-empty manufacturer strings and
two non-empty zone user labels. Their exact values remain operator-private;
this public evidence records only typed presence and the future stability
outcome. eBUS comparator and fallback evidence belongs to the platform evidence
contract and is not published in this eeBUS-native record.

## Claim Boundary

This evidence grounds protocol source identity and declared granularity. It is
not a synchronized two-window campaign, comparator dossier, metrological
accuracy claim, semantic promotion, or consumer exposure. A source being
protocol-eligible does not prove that its eBUS peer is readable or equivalent.
An eeBUS-native result proves exact identity, typed presence, and PRE/POST
restart stability only; it is not cross-protocol equivalence or a claim that
the value can never change.

The public record contains no peer fingerprint, persistent pairing identifier, native
service/device/entity/feature selector, network coordinate, read token, private
key, PEM private material, trust-store byte, or `candidate_ref`.
